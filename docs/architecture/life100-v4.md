# Life100 v4 — Private knowledge platform
Status: proposed, architecture before implementation. No personal data in this document.
## 1 Requirements
Single owner, multiple devices; typed objects, rich documents, Markdown import/export, backlinks, collections, projects/tasks/goals, journal, local search, AI research and proposed edits, attachments and private backup. Core editing offline. Proposed targets: 50k objects, 100k edges, local search p95 <100ms, online sync p95 <2s under healthy network, zero public personal records. Measure before claiming.
## 2 Architecture
React/TypeScript PWA -> IndexedDB and outbox -> authenticated HTTPS gateway -> modular backend -> PostgreSQL (authoritative object store, revisions, relations, transactional outbox), object storage (attachments), private GitHub (versioned export, not primary database). AI adapters call providers only on explicit user-selected context. Initially modular monolith; no required Kafka, Redis, Kubernetes or separate graph database. Existing GitHub Pages shell is public; it cannot enforce owner-only site access. For private shell use a dedicated hostname behind an identity-aware proxy and disable public Pages after successful migration. Retain public source only if desired. Private deployment hosting and identity provider require account configuration.
## 3 Contracts
Object: id, workspaceId, typeId, title, canonical document content, typed properties, createdAt, updatedAt, revision, deletedAt. Type definition: fields, validation, templates. Relations: sourceId, targetId, kind, unique edge constraint, workspace scope. Document content: versioned block schema, Markdown import/export with explicit lossy-format warnings. Stable IDs, no titles as primary keys. Attachment: object ID, MIME, size, checksum, encrypted storage key. Operation: operationId, deviceId, workspaceId, expectedRevision, payload, schemaVersion. API: GET /v1/bootstrap, GET /v1/changes?cursor, POST /v1/operations, GET /v1/objects/:id, POST /v1/search, POST /v1/ai/runs, POST /v1/ai/proposals/:id/apply, POST /v1/exports. Session-derived owner scope; reject caller-supplied cross-workspace access.
## 4 Flows and states
Local edit transaction updates IndexedDB and durable outbox atomically; replay idempotently on reconnect. Server validates identity, schema, revision, writes object and event atomically; clients pull cursor-ordered changes, reconcile acknowledgments. Conflicts retain both variants and require explicit resolution initially; CRDT editing considered after baseline tests. Tombstones retained until safe compaction. AI run requested -> authorized -> provider executing -> proposed -> accepted/rejected/expired; apply only against matching revision. Web results and notes untrusted; citations stored with AI drafts. No autonomous writes. Search local FTS/fuzzy, then optional pgvector behind explicit opt-in. Export portable Markdown + JSON metadata + relationships + attachments manifest; encrypted backup separate from human-readable local export.
## 5 Failure and security
Threats: public asset exposure, XSS, stolen device/session, cross-owner access, malicious document instructions, AI disclosure, compromised backup credentials, replay, conflict, quota, provider failure. Identity-aware proxy and verified OIDC subject allowlist, deny by default on API; short-lived secure HttpOnly session cookie, CSRF protection, CSP, no secrets in bundles, least-privilege credentials, rate/cost limits. Local cache remains sensitive; sign-out offers local wipe after export/confirmation. Encrypt sensitive backups with authenticated encryption and versioned key management; recovery key stored separately; avoid inventing crypto protocol. Git history persists plaintext deletes: do not upload plaintext private records until owner explicitly accepts. Server-readable data is not end-to-end encrypted; distinguish transport/at-rest protection from E2EE. AI providers receive only explicitly selected context, no background indexing of journals/finance/health without opt-in. Logs exclude note text, prompts, secrets. Retry with jitter, bounded queues, visible conflicts, backup restore tests.
## 6 Components and reuse
COSMIC patterns to evaluate: adapter interfaces, event envelopes, run lifecycle, typed contracts, idempotency, durable outbox, observability, integration testing. No verified COSMIC source access in current connector search; reuse patterns, not claim code reuse. Avoid ROS/DDS, Zenoh, Redpanda, robotics execution and Kubernetes unless demonstrated need. Candidate libraries: Tiptap/ProseMirror for blocks, IndexedDB/Dexie, PostgreSQL FTS, pgvector optional, OpenTelemetry. Verify compatibility before locking dependencies. Domain modules independent from UI and provider SDKs.
## 7 Rollout
P0 owner identity and private hosting, credential setup, restore drill, no remote upload before security gates. P1 typed objects and migration from current localStorage vault, keep raw backup, dual-read migration tests. P2 editor, backlinks, collections, object views, search. P3 offline outbox and sync, encrypted GitHub backups. P4 AI tools and revision proposals, optional MCP read-only then approved write. P5 richer planning and metrics, visual polish. Feature flags and reversible migrations; preserve existing public shell until private URL is validated, then retire public deployment if owner wants. No real data in tests/CI. Separate docs PR from feature implementation.
## 8 Observability
Structured request IDs, operation IDs, duration, sync lag, retry counts, conflict rate, backup age, AI cost/tokens, provider error counters. Redact all private content. Trace client -> gateway -> database/provider. Alerts for failed backup and unauthorized attempts; no telemetry content.
## 9 Verification
Unit/schema tests, auth denied for unauthenticated/other subject, CSRF and XSS cases, sync duplicate/reorder/offline/conflict tests, provider prompt-injection cases, encrypted export/restore round trip, migration fixtures, desktop/mobile browser checks, accessibility, load targets. CI green before merging. Private production acceptance: incognito denied, owner login works, API unauthorized 401/403, cross-device test, public source/asset scan for secrets, restore drill.
## 10 Limits and decisions
Existing app uses localStorage and manual plaintext snapshot sync via optional bearer-token worker; not a fully private authenticated platform today. GitHub connector cannot provision identity provider, private hosting or credentials; no access to COSMIC implementation found. No claim of completed security rollout. Decide hosting, account/identity, backup encryption recovery and AI provider billing during provisioning. Keep architecture public-safe and data private.
